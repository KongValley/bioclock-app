# BioClock 功能优化与验收记录（2026-11-02）

本轮完成通知、导入、导出和历史记录的修复，并在 MuMu + Expo Go 中实测主流程。自动化检查、主流程及本地通知投递通过；通知点击被 Expo Go 原生崩溃阻塞，不能判为通过。正式发布验收仍需独立安装包复测该项，以及真机长时通知、系统生物识别和 iOS 验证。

## 环境与数据隔离

- Windows / PowerShell，Node 24.19.0，Expo SDK 58 / Expo Go 58.0.5，Android 15 MuMu，ADB `127.0.0.1:16416`。
- 模拟器用 `.expo-verify/qa-project` 的源码副本和独立数据库测试；原项目数据库名保持 `bioclock.db`，没有清空或修改原有记录。
- 主流程、换机恢复分别使用 `bioclock-qa-20261102.db`、`bioclock-qa-restore-20261102.db`；通知权限关闭 / 开启分别使用 `bioclock-qa-notify-20261102.db`、`bioclock-qa-notify-exact-20261102.db`。
- 测试数据均为合成数据；截图和导出文件保留在忽略目录 `.expo-verify/qa/`，不纳入版本控制。
- Expo Go 的项目 slug 不足以隔离 SQLite，测试副本必须使用不同数据库文件名。

## 本轮修复

| 问题 | 修复结果 | 验证 |
| --- | --- | --- |
| 未来已跳过的计划仍可能收到提醒 | 同时检查打卡关联和状态，不再重复提醒 | 注射 / 口服回归测试 |
| 口服当天原提醒时间已过，免打扰顺延后的时间仍在未来，却被丢弃 | 先顺延，再判断过期 | 通知回归测试 |
| 口服通知覆盖多出一天；回前台未续排 | 精确覆盖含当天的 14 天，从后台回前台续排 | 排程及生命周期测试 |
| 重排先清空，读库失败会丢失已有通知 | 草稿全部准备好后再替换旧通知 | 失败、并发排队测试 |
| 导入标签、停用状态和疗效事件失败可能留下部分数据 | 全部写入放进同一事务，失败全部回滚 | 真 SQLite 故障注入测试 |
| 已停用线导入历史可能重复建线或报冲突 | 复用原线补录停用前历史；停用后新打卡明确提示先恢复 | SQLite 边界测试 |

| CSV / PDF 缺少状态，已用与跳过 / 漏用不可区分 | 增加状态列；PDF 明确依从性使用全部历史 | 格式回归、实际文件检查 |
| Expo Go PDF 导出报 Missing READ permission | 通过本地 URI 读取打印文件，再写入应用缓存 | 模拟器重现、修复后成功导出及渲染 |
| 方案停用后历史记录页显示 0 条，旧方案记录无法编辑 | 列表索引全部方案，编辑按原记录定位所属方案 | 模拟器停用后的注射 / 口服显示及保存 |

## 通知设备验证

1. 原始系统设置：Expo Go 通知关闭，精确闹钟关闭。关闭时排程仍能进入系统队列，23:53 的短时测试没有按时展示。
2. 临时开启通知和精确闹钟，使用独立测试数据库，口服提醒设置为 23:57，免打扰起止均为 00:00。
3. 系统队列显示 `window=0 exactAllowReason=permission`；原生日志确认 23:57:00 收到事件，通知栏实际显示「今天该服用 QA Oral」，投递通过。模拟器媒体 / 通知流静音，本轮未以声音作为通过依据。
4. 点击该通知时，Expo Go 进程原生崩溃：`Unable to start activity ... host.exp.exponent.LauncherActivity`，原因 `Cannot access database on the main thread`。堆栈位于 Expo Go 启动器，BioClock 的 JS 点击路由未能完成，因此该项标为阻塞，需要独立 APK 复测，不能据此宣称点击链路通过。
5. 测试结束恢复原有通知和精确闹钟关闭状态。原生提醒参数正确入队 / 投递，不代表已覆盖厂商后台限制、重启恢复或长时运行。

补充观察：从备份恢复的测试项目没有建立自定义 Android 通知渠道，Expo Go 在投递时回退到默认渠道；该次通知仍正常显示。独立安装包应一并复测渠道、权限及点击链路。

## 验收边界与保留限制

- 本轮使用 Expo Go，没有生成或发布 APK；Android export 验证的是 Metro / Hermes 构建。
- 厂商省电、杀进程、重启、跨天 / 夏令时、长时间离线后的系统投递，以及 iOS 真机通知尚未做长时验证。
- 模拟器没有已录入的生物识别，本轮未验收应用锁解锁流程。
- 稍后提醒分钟数仍只有配置，系统通知快捷操作尚未实现；日历仍只展示注射计划。
- 已有激活方案时导入换机文件仍为合并；从引导页恢复才会按快照建立方案结构。
- 本轮未改网页补录工具，也未重做其完整浏览器验收。
