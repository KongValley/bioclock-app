# BioClock 导入文件格式（v3）

设置 → 导入数据 支持从 **Excel（.xlsx / .xls）或 JSON** 文件批量补录药物、注射、口服打卡和症状。
可以用 [`tools/import-editor`](../tools/import-editor) 网页工具填写导出，也可以按本文档手写。

v3 对应 v6 的「治疗组合 + 疗效事件」模型：一个治疗方案里可以同时有多条注射线（皮下 / 静脉）和口服线，
注射与口服的打卡记录统一存进 `dose_log`。v1/v2 文件仍然可以导入，见文末[版本兼容](#版本兼容)。

## 版本

| 版本 | 顶层新增 | 说明 |
| --- | --- | --- |
| v1 | `injections`、`symptoms` | 只有注射和症状，没有药物与口服段 |
| v2 | `medications`、`oralLogs` | 注射记录增加 `status`、`lineLabel` |
| v3 | `lineStates`、`efficacyEvents` | 当前版本；导出会带上停用时间与疗效事件 |

## JSON 顶层结构

```json
{
  "format": "bioclock-import",
  "version": 3,
  "medications": [],
  "injections": [],
  "oralLogs": [],
  "symptoms": [],
  "lineStates": [],
  "efficacyEvents": []
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `format` | 是 | 固定 `"bioclock-import"`，用来防止选错文件 |
| `version` | 是 | 当前支持 `1`、`2`、`3` |
| `medications` | 否 | 药物数组，见下 |
| `injections` | 否 | 注射打卡数组，见下 |
| `oralLogs` | 否 | 口服打卡数组，见下 |
| `symptoms` | 否 | 症状记录数组，见下 |
| `lineStates` | 否 | v3：当前方案各用药线的停用时间 |
| `efficacyEvents` | 否 | v3：疗效下降 / 失效 / 不耐受等事件 |
| `exportedAt` | 否 | App 导出时写入的时间，仅作说明，导入时忽略 |

数组可以只填一个，但不能都为空；**每个数组最多 2000 条**，超出请拆文件。
只有 `medications` 时不需要先建治疗方案；只要包含注射或口服记录，就必须已有激活的治疗方案。
`lineStates` / `efficacyEvents` 会按「用药线名称 → 药名」匹配当前激活方案，匹配不到的会跳过。

## 时间

所有时间都是**本地时间字符串**，不写时区：

```
YYYY-MM-DD HH:mm
```

也接受 `2026-03-01T09:00`、`2026/3/1 9:00`、带秒的写法。导入时按手机本地时区解释。
不存在的日期（如 `2026-02-30`）会被拒绝并提示第几条。

## 药物 `medications`

```json
{
  "name": "甲氨蝶呤",
  "genericName": "甲氨蝶呤",
  "brandNames": ["MTX"],
  "route": "oral",
  "defaultDose": 10,
  "unit": "mg",
  "catalogKey": null,
  "extra": { "source": "paper-card" }
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 药名，最多 40 个字；也是记录里 `medication` 的主要匹配依据 |
| `genericName` | 否 | 通用名，最多 40 个字 |
| `brandNames` | 否 | 商品名数组；也接受用顿号、逗号、分号、斜杠分隔的文本 |
| `route` | 否 | `sc`（皮下）、`iv`（静脉输注）、`oral`（口服），默认 `sc` |
| `defaultDose` | 否 | 默认剂量，数字，不能为负；不填表示未记录 |
| `unit` | 否 | 单位，最多 20 个字；新建药时留空按 `mg` |
| `catalogKey` | 否 | 内置药物目录的稳定标识；自定义药留空。全库唯一，重复会写入失败 |
| `extra` | 否 | 任意 JSON 对象，原样保存；核心逻辑不读取 |

`route` 也接受中文：`皮下`、`皮下注射`、`静脉`、`静脉输注`、`口服`。

### 药物合并

导入时按以下别名集合认领已有药物：

1. 先按 `medication.name` 精确匹配（忽略大小写、空格、括号、`-`、`/` 等分隔符）；
2. 再按「药名 + 通用名 + 商品名 + 内置目录里该药的名称」匹配；
3. 同时命中多条时优先内置药。

- **命中已有药**：只补空字段、合并商品名，不覆盖用户已有值；内置药的名称、通用名、商品名和给药途径来自目录，不修改。已有药不会合并 `extra`。
- **匹配不到**：新建一条自定义药（`isBuiltin: false`，颜色自动分配，`unit` 默认 `mg`）。

## 注射记录 `injections`

```json
{
  "injectedAt": "2026-03-15 09:00",
  "medication": "阿达木单抗",
  "dose": 40,
  "unit": "mg",
  "site": "腹部左上",
  "lotNumber": "AB12345",
  "note": "第 1 针",
  "status": "done",
  "lineLabel": "阿达木单抗"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `injectedAt` | 是 | 注射时间 |
| `medication` | 否 | 药名、通用名或商品名；留空时归到当前方案的注射主药 |
| `dose` | 否 | 剂量，数字，不能为负；不填表示未记录 |
| `unit` | 否 | 单位，默认取药物单位，再退到 `mg` |
| `site` | 否 | 注射部位，默认 `abdomen_ul`，见下表 |
| `lotNumber` | 否 | 批号，最多 60 个字 |
| `note` | 否 | 备注 |
| `status` | 否 | `done`（已用，默认）、`skipped`（跳过）、`missed`（漏用） |
| `lineLabel` | 否 | 用药线名称，用于同一方案里有多条注射线时消歧 |

### 用药线匹配顺序

1. 有 `lineLabel` 且与当前方案的某条注射线名称完全一致 → 用这条线；
2. 否则按 `medication` 认药，找这种药在当前方案里的注射线；
3. 这种药还没有注射线 → **自动新建一条**（见下）；
4. 没有写 `medication` → 用当前方案的注射主药，没有主药时用第一条注射线；
5. 写了 `medication` 但数据库和 `medications` 段里都找不到这个药 → 该条跳过，计入「无对应用药线」。

### 自动新建注射线

- 按该药在本次文件里的注射记录推算**中位间隔**（只在 0.5–365 天之间取样）；算不出来按 28 天。
- 只建一个 `maintenance` 阶段（`repeatCount: 0`，长期重复），`anchor: 'actual'`，按时窗口 2 天。
- 剂量取该药最近一条导入记录的剂量/单位，没有则用药物默认剂量/单位。
- 方案里还没有主药时，这条新线设为主药；否则默认 `syncWithHost: true`，跟随主药针日。

### 注射部位

| 值 | 含义 |
| --- | --- |
| `abdomen_ul` / `abdomen_ur` / `abdomen_ll` / `abdomen_lr` | 腹部左上 / 右上 / 左下 / 右下 |
| `thigh_l` / `thigh_r` | 左大腿 / 右大腿 |
| `arm_l` / `arm_r` | 左上臂 / 右上臂 |

也可以直接写中文：`腹部左上`。静脉输注记录同样要求填一个合法值，通常保持默认即可。

## 口服打卡 `oralLogs`

```json
{
  "takenAt": "2026-03-16 20:00",
  "medication": "甲氨蝶呤",
  "status": "done",
  "dose": 10,
  "unit": "mg",
  "note": "晚饭后",
  "lineLabel": "甲氨蝶呤"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `takenAt` | 是 | 打卡时间；也接受别名 `loggedAt` |
| `medication` | 否 | 药名、通用名或商品名；留空时归到当前方案的第一条口服线 |
| `status` | 否 | `done`（已服，默认）、`skipped`（跳过）、`missed`（漏服） |
| `dose` | 否 | 剂量，数字，不能为负 |
| `unit` | 否 | 单位，默认取药物单位 |
| `note` | 否 | 备注 |
| `lineLabel` | 否 | 用药线名称，用于多条口服线时消歧 |

用药线匹配顺序与注射相同：`lineLabel` → `medication` → 第一条口服线。
药没有对应用的口服线时会**自动新建**：从该药最早一条打卡的当天开始，**每天一次、长期服用、09:00 提醒**。
如果既没有 `medication`、方案里也没有口服线，该条跳过并计入「无对应用药线」。

## 症状记录 `symptoms`

```json
{
  "loggedAt": "2026-03-30 20:30",
  "severity": 4,
  "painScore": 6,
  "tags": ["发热", "乏力"],
  "temperature": 37.8,
  "note": "晚上加重",
  "injectionAt": "2026-03-29 09:10"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `loggedAt` | 是 | 记录时间 |
| `severity` | 否 | 整体严重程度 1–5，默认 3 |
| `painScore` | 否 | 临床疼痛评分 NRS 0–10，`0` 表示确实无痛，不填表示未评估 |
| `tags` | 否 | 症状名称数组，自动去重；单个最多 20 个字，新名称会补进症状标签表 |
| `temperature` | 否 | 体温，30–45 |
| `note` | 否 | 备注 |
| `injectionAt` | 否 | 关联同一时刻的用药打卡记录（注射或口服均可）；按分钟匹配，找不到时按未关联处理 |

`severity` 和 `painScore` 是两个独立维度，导入时不会互相换算。

## v3：用药线状态 `lineStates`

```json
{
  "lineLabel": "阿达木单抗",
  "medication": "阿达木单抗",
  "kind": "injection",
  "endedAt": "2026-10-01 09:00"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `lineLabel` | 否 | 优先按线名匹配当前方案 |
| `medication` | 否 | 线名匹配不到时按药名匹配 |
| `kind` | 是 | `injection` 或 `oral` |
| `endedAt` | 否 | 停用时间；`null` 表示恢复到使用中 |

## v3：疗效事件 `efficacyEvents`

```json
{
  "lineLabel": "阿达木单抗",
  "medication": "阿达木单抗",
  "kind": "failed",
  "occurredAt": "2026-10-01 09:30",
  "note": "医生评估后换药"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `lineLabel` | 否 | 优先按线名匹配 |
| `medication` | 否 | 线名匹配不到时按药名匹配 |
| `kind` | 是 | `reduced / failed / intolerance / antibody / other`，也接受中文 |
| `occurredAt` | 是 | 事件发生时间，不能晚于今天 |
| `note` | 否 | 备注 |

导入时会按事件时间重新统计「当时已完成次数」，不直接信任文件里的旧快照。
事件关联到当前激活方案的用药线；匹配不到的行会跳过。

## Excel 格式（推荐）

模板：[`tools/import-editor/templates/bioclock-import-template.xlsx`](../tools/import-editor/templates/bioclock-import-template.xlsx)，
包含 **注射记录 / 症状记录 / 药物 / 口服打卡 / 填写说明** 五张工作表。
工作表名称按下面的名称识别（也支持「注射」「症状」「药品」「药物目录」「口服记录」等别名，英文名不区分大小写）；`填写说明` 不参与导入。

**「注射记录」**

| 注射时间 * | 药物 | 剂量 | 单位 | 部位 | 批号 | 备注 | 状态 | 用药线 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 2026-03-15 09:00 | 阿达木单抗 | 40 | mg | 腹部左上 | AB12345 | 第一针 | 已用 | 阿达木单抗 |

**「症状记录」**

| 记录时间 * | 严重程度 | 疼痛评分 | 症状 | 体温(℃) | 备注 | 关联注射时间 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-03-30 20:30 | 4 | 6 | 发热、乏力 | 37.8 | 晚上加重 | 2026-03-29 09:10 |

**「药物」**

| 药名 * | 通用名 | 商品名 | 给药途径 | 默认剂量 | 单位 | 目录标识 |
| --- | --- | --- | --- | --- | --- | --- |
| 甲氨蝶呤 | 甲氨蝶呤 | MTX | 口服 | 10 | mg | |

**「口服打卡」**

| 记录时间 * | 药物 | 状态 | 剂量 | 单位 | 备注 | 用药线 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-03-16 20:00 | 甲氨蝶呤 | 已用 | 10 | mg | 晚饭后 | 甲氨蝶呤 |

规则：

- 时间可以写文本 `2026-03-15 09:00`，也可以直接用 Excel 的日期时间单元格或日期序列号。
- 表头支持别名：`药名/药品`、`注射部位/部位`、`批次/批号`、`记录时间/时间`、`症状标签/症状`、`给药途径/途径` 等；括号里的单位会被忽略。
- 症状用顿号、逗号、分号、斜杠分隔，导入时会去重；新症状会自动加进症状标签表。
- 状态可以写英文 `done / skipped / missed`，也可以写中文 `已用 / 跳过 / 漏用`（也接受 `已注射`、`已服用`、`漏服` 等）。
- 给药途径可以写 `sc / iv / oral`，也可以写 `皮下注射 / 静脉输注 / 口服`。
- **自定义药随文件创建**：在「药物」表里加一行即可；注射/口服记录里引用的药名，如果不在「药物」表或 App 里，不会凭空建药，会按「无对应用药线」跳过。
- **找不到用药线会自动建线**：药已经存在（或刚由「药物」表创建），但当前方案里没有对应的注射线/口服线时，导入会补一条，并在确认框里显示将新建几条线。
- 工作表名都识别不到时，用第一张表按表头自动判断是注射、症状、药物还是口服；有多个可识别表时按工作表名分别读取。
- 空白行自动跳过；示例行可以直接删掉或覆盖。
- App 导出的 `.xlsx` 还会带一张「用药线」工作表，仅用于阅读，导入时忽略。

## 合并与去重

| 对象 | 规则 |
| --- | --- |
| 药物 | 按药名 / 通用名 / 商品名 / 内置目录名称互认；命中已有药只补空字段并合并商品名，不覆盖已有值 |
| 注射 / 口服打卡 | 按「打卡时间 + 用药线」判断；同一时刻不同用药线不算重复 |
| 症状 | 按「记录时间 + 严重程度 + 排序后的症状组合」判断 |
| 症状标签 | 按名称忽略大小写去重；文件里的新标签会补进症状标签表 |

文件内部也会去重：同一文件里重复的打卡或症状只保留第一条。

## 导入行为

- **事务写入**：整个文件在一个数据库事务里写入，中途失败会回滚，不会留下半截数据。
- **需要激活方案**：只要包含注射或口服记录，就必须已有激活的治疗方案，否则整体失败。
- **不改已有方案**：导入不会修改已有用药线的阶段、剂量、锚点、窗口和提醒设置，只在缺少对应药线时新增。
- **结果提示**：返回新写入的注射数、口服打卡数、症状数、跳过的重复数、无对应用药线的条数、新建标签数、新建药物数和新建用药线数；确认框会在写入前预览这些数量。
- **通知**：写入成功后由 store 重新排程本地通知（`rescheduleAll()`）；排程失败不回滚数据。
- **标签播种**：内置症状标签只播种一次，导入新增的标签不会在下次启动时被覆盖或删除。

## 版本兼容

v1 文件结构如下，仍然可以直接导入：

```json
{
  "format": "bioclock-import",
  "version": 1,
  "injections": [],
  "symptoms": []
}
```

- v1 没有 `medications` 和 `oralLogs`，药名只能按数据库里已有的药物匹配。
- v1 的注射记录没有 `status` 和 `lineLabel`，导入时状态按 `done`、用药线按「药名 → 当前方案注射主药」解析。
- 如果 v1 记录写的药名在数据库里不存在，该条会被跳过并计入「无对应用药线」，不会自动新建药物。
- 导入后统一写进 v5 的 `treatment` / `dose_log` 模型，不再产生旧的 `regimen` / `injection` 数据。
