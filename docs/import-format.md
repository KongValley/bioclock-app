# BioClock 导入文件格式（v1）

设置 → 导入数据 支持从 **Excel（.xlsx / .xls）或 JSON** 文件批量补录注射和症状。
用 [`tools/import-editor`](../tools/import-editor) 网页工具填写导出，或按本文档手写。

## Excel 格式（推荐）

工作簿可以包含两个工作表（名称里带「注射」「症状」即可识别）：

**「注射记录」**

| 注射时间 * | 药物 | 剂量 | 单位 | 部位 | 批号 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-03-15 09:00 | 阿达木单抗 | 40 | mg | 腹部左上 | AB12345 | 第一针 |

**「症状记录」**

| 记录时间 * | 严重程度 | 疼痛评分 | 症状 | 体温(℃) | 备注 | 关联注射时间 |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-03-30 20:30 | 4 | 6 | 发热、乏力 | 37.8 | 晚上加重 | 2026-03-29 09:10 |

规则：

- 时间可以写文本 `2026-03-15 09:00`，也可以直接用 Excel 的日期时间单元格。
- 表头支持别名：`药名/药品`、`部位`、`批次`、`记录时间/时间`、`症状标签` 等；括号里的单位会被忽略。
- 症状用顿号、逗号、分号分隔，导入时会去重；新症状会自动加进症状标签表。
- 只有一个工作表时，按表头自动判断是注射还是症状。
- 空白行自动跳过；示例行可以直接删掉或覆盖。
- 模板：[`tools/import-editor/templates/bioclock-import-template.xlsx`](../tools/import-editor/templates/bioclock-import-template.xlsx)

## JSON 格式

顶层结构：

```json
{
  "format": "bioclock-import",
  "version": 1,
  "injections": [],
  "symptoms": []
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `format` | 是 | 固定 `"bioclock-import"`，用来防止选错文件 |
| `version` | 是 | 当前只支持 `1` |
| `injections` | 否 | 注射记录数组，见下 |
| `symptoms` | 否 | 症状记录数组，见下 |

两个数组可以只填一个，但不能都为空。单次最多 2000 条。

## 时间

所有时间都是**本地时间字符串**，不写时区：

```
YYYY-MM-DD HH:mm
```

也接受 `2026-03-01T09:00`、`2026/3/1 9:00`、带秒的写法。导入时按手机本地时区解释。
不存在的日期（如 `2026-02-30`）会被拒绝并提示第几条。

## 注射记录 `injections`

```json
{
  "injectedAt": "2026-03-15 09:00",
  "medication": "阿达木单抗",
  "dose": 40,
  "unit": "mg",
  "site": "abdomen_ul",
  "lotNumber": "AB12345",
  "note": "第 1 针"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `injectedAt` | 是 | 注射时间 |
| `medication` | 否 | 药名或通用名。匹配不到已录入药物时，归到当前方案的药 |
| `dose` | 否 | 剂量，数字，不能为负；不填表示未记录 |
| `unit` | 否 | 单位，默认取药物单位或 `mg` |
| `site` | 否 | 注射部位，默认 `abdomen_ul`，见下表 |
| `lotNumber` | 否 | 批号 |
| `note` | 否 | 备注 |

### 注射部位

| 值 | 含义 |
| --- | --- |
| `abdomen_ul` / `abdomen_ur` / `abdomen_ll` / `abdomen_lr` | 腹部左上/右上/左下/右下 |
| `thigh_l` / `thigh_r` | 左/右大腿 |
| `arm_l` / `arm_r` | 左/右上臂 |

也可以直接写中文：`腹部左上`。

导入注射记录前必须已有用药方案（Settings 里的病种/药物/间隔）。没有方案时导入会整体失败，不会写入半截数据。

## 症状记录 `symptoms`

```json
{
  "loggedAt": "2026-03-30 20:30",
  "severity": 4,
  "painScore": 6,
  "tags": ["发热", "乏力"],
  "temperature": 37.8,
  "note": "晚上加重",
  "injectionAt": "2026-03-29 09:10"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `loggedAt` | 是 | 记录时间 |
| `severity` | 否 | 整体严重程度 1–5，默认 3 |
| `painScore` | 否 | 临床疼痛评分 NRS 0–10，`0` 表示确实无痛，不填表示未评估 |
| `tags` | 否 | 症状名称数组，自动去重；新的名称会补进症状标签表 |
| `temperature` | 否 | 体温，30–45 |
| `note` | 否 | 备注 |
| `injectionAt` | 否 | 关联一条注射记录（时间需完全一致）；找不到时按未关联处理 |

## 导入行为（JSON 与 Excel 相同）

- **重复跳过**：注射按「时间 + 药物」、症状按「时间 + 严重程度 + 症状组合」判断，已存在则跳过，并在结果里提示跳过条数。
- **药物匹配**：`medication` 先按药名/通用名匹配当前数据库里的药；匹配不到就用当前方案关联的药。不会自动新建药物。
- **症状标签**：文件里的新症状会自动加入「症状标签」，之后记录时能直接选。
- **事务写入**：整个文件在一个数据库事务里写入，中途失败会回滚。写入完成后会重新计算下次注射时间并重排本地通知。
- **不影响方案**：导入不会修改用药方案、剂量阶段和提醒设置。
