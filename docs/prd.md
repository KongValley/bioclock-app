## 1. 文档目的

本文档描述 BioClock **当前已实现**的产品需求、行为规则和验收标准，用于：

- 对齐产品、设计和开发的预期；
- 作为新增功能的回归基线；
- 判断一个改动是否破坏既有产品行为。

不包含未落地的路线图。用户操作说明见 [用户手册](./user-guide.md)。

## 2. 背景与问题

需要长期自我注射生物制剂的患者，通常面临：

1. 记不清上次什么时候注射、下次该什么时候注射；
2. 治疗组合复杂（多种注射药 + 口服药），纸笔或备忘录难以维护；
3. 需要轮换注射部位，但容易连续打在同一侧；
4. 症状和用药时间的关系难以回顾；
5. 复诊时缺少结构化记录；
6. 换手机后历史数据容易丢失；
7. 健康数据敏感，不希望上传云端。

BioClock 用纯本地记录 + 本地通知 + 导出文件解决这些问题，不介入医疗决策。

## 3. 产品目标与非目标

### 3.1 目标

- 让用户在 30 秒内完成一次注射 / 口服 / 症状登记。
- 让用户打开 App 就能知道「下一次用药是什么时候、该做什么」。
- 支持注射 + 口服的联合治疗方案，以及负荷 / 维持阶段。
- 支持「从下一针起」调整间隔，不重算历史。
- 提供可给医生看的导出文件，以及可完整迁移的换机备份。
- 所有数据留在本机，无账号、无网络、无埋点。

### 3.2 非目标

- 不诊断疾病、不判断疗效、不建议停药 / 换药 / 调整剂量。
- 不做账号、云同步、社交、处方识别。
- 不做自动云备份。
- 不替代医生、护士或药品说明书。
- 不以 Web 作为完整使用平台。

## 4. 目标用户与场景

### 4.1 用户

需要长期使用生物制剂的慢病患者，常见病种：

克罗恩病、溃疡性结肠炎、银屑病、银屑病关节炎、强直性脊柱炎、类风湿关节炎、特应性皮炎、慢性自发性荨麻疹、系统性红斑狼疮、化脓性汗腺炎、重度嗜酸性哮喘、非感染性葡萄膜炎。

用户可能同时有多个病种，也可能同时使用多种注射药和口服药。

### 4.2 核心场景

| 场景 | 用户目标 | 产品响应 |
| --- | --- | --- |
| 该打针了 | 不错过注射时间 | 本地通知 + 首页倒计时 + 一键登记 |
| 忘了上次 | 快速确认上次 / 下次 | 首页下次卡片 + 记录时间线 |
| 今天要吃药 | 知道口服任务并打卡 | 首页今日待办 + 口服完成 / 跳过 |
| 打完不舒服 | 记录症状 | 严重度、NRS 疼痛、标签、体温、关联注射 |
| 医生调了间隔 | 只影响下一针 | 「从下一针起」调整，历史不重算 |
| 疗效变化 | 记录并停用某条线 | 疗效事件 + 停用 / 恢复用药线 |
| 复诊 | 交一份可读记录 | PDF / Excel 导出 |
| 换手机 | 完整带走数据 | 换机快照 + 引导页恢复 |

## 5. 产品范围

当前版本包含：

- 四步首次引导 + 换机恢复入口；
- 治疗组合（多注射线 / 口服线）、阶段、锚点、窗口、停用；
- 注射打卡、口服打卡、症状记录、疗效事件；
- 排程、倒计时、日历、依从性、症状时间线；
- 本地通知、免打扰、通知点击直达；
- 部位轮换；
- 导入（Excel / JSON v3）、导出（CSV / Excel / JSON / PDF）、换机快照；
- 应用锁、主题、药物 / 病种 / 症状标签管理、清空数据。

## 6. 信息架构

```text
今天 / 记录 / 日历 / 趋势 / 设置
  ├─ 首次引导：病种 → 药物 → 方案 → 提醒
  ├─ 登记弹窗：注射 / 口服 / 症状
  └─ 设置：方案 / 药物 / 病种 / 标签 / 提醒 / 安全 / 外观 / 数据 / 关于
```

## 7. 功能需求

### FR-01 首次引导

**需求**

- 支持 12 个病种多选、按病名 / 别名搜索、按 4 组展示。
- 按病种过滤药物目录；多病种取并集；标注「常用」一线药。
- 支持自定义药物：药名、通用名、商品名、给药途径、默认剂量、单位。
- 支持方案阶段编辑、无负荷模式、上次注射时间、前 5 针预览。
- 支持提醒时间、提前 3 / 2 / 1 / 0 天、免打扰、通知权限。
- 支持从换机备份恢复。

**验收标准**

1. 完成引导后必须存在一个激活治疗方案和一条用药线。
2. 注射方案必须至少有一个阶段；`repeatCount = 0` 表示无限维持。
3. 上次注射时间不能晚于当前时间 + 24 小时（实现保留了时区余量）。
4. 提醒偏移不能为空，时间格式为 `HH:mm`。
5. 设置写入 `disease_ids`、`onboarded_at`、`dnd_start`、`dnd_end`，并创建一条提醒规则。
6. 引导页预览的日期 / 剂量必须与保存后的排程一致。
7. 从备份恢复成功后直接进入首页，不再要求手动建方案。

### FR-02 治疗组合与用药线

**需求**

- 一个治疗方案可包含多条注射线和口服线。
- 注射线可设主药、跟随主药、锚点、按时窗口、阶段。
- 口服线可设开始日期、疗程天数、频率（每天 / 每周 N 次 / 固定周几）、提醒时间。
- 支持停用 / 恢复用药线和治疗方案。

**验收标准**

1. 同一时间至多一个激活治疗方案。
2. 一个方案最多一条主药注射线。
3. 同一种药在同一 `kind` 下不能重复；不同途径可以并存。
4. 口服线不能设为主药或同步线。
5. 停用用药线后不再生成未来计划，历史记录保留。
6. 修改 `medicationId` 时也必须做重复校验。

### FR-03 注射打卡

**需求**

- 记录用药线、时间、剂量、单位、部位、批号、备注。
- 支持编辑、删除、补录。
- 静脉输注不显示部位选择。
- 保存后重新计算下一针并重排通知。

**验收标准**

1. `status = done` 必须有实际时间。
2. 皮下注射部位为 8 个枚举之一；静脉可为空。
3. 删除打卡后下一次计划重新计算。
4. 通知排程失败不回滚打卡数据，但必须提示用户。

### FR-04 口服打卡

**需求**

- 记录用药线、时间、完成 / 跳过、剂量、单位、备注。
- 支持编辑、删除。
- 跳过不记录服用时间，但保留计划时间。

**验收标准**

1. 跳过 / 漏用允许 `takenAt = null`。
2. 记录按计划日或实际时间归组，不重复计数。
3. 删除后依从性和趋势同步更新。

### FR-05 症状记录

**需求**

- 记录时间、严重度 1–5、NRS 疼痛 0–10、标签、体温、备注。
- 可关联最近 5 条注射记录。
- 标签可维护；历史记录保存标签快照。

**验收标准**

1. 严重度必须在 1–5。
2. 疼痛为空或 0–10。
3. 删除标签不改变历史记录里的文字。
4. 删除打卡只把症状的关联置空，不删除症状。

### FR-06 排程

**需求**

- 下次时间实时推导，不落库。
- 支持实际 / 计划两种锚点。
- 负荷 / 维持阶段按顺序推进；支持 `effective_from`。
- 支持同步线跟随主药。
- 支持按时窗口和状态（done / due / upcoming / overdue / missed）。
- 日历展示未来 200 针注射计划。

**验收标准**

1. 无记录时首针从今天本地零点开始。
2. 实际锚点：下一针 = 上一针实际时间 + 当前阶段间隔。
3. 计划锚点：下一针 = 上一针计划时间 + 间隔。
4. 负荷阶段按 `repeatCount` 总针数推进；0 表示无限。
5. 调整间隔后旧阶段保留，历史记录仍按旧间隔显示。
6. 停用线不生成未来计划；停用后补录仍可见。

### FR-07 通知

**需求**

- 本地通知，不联网。
- 滚动预排 56 天，单次最多 60 条。
- 注射提醒按提前天数 + 提醒时间生成；偏移包含 0 时，当天 20:00 加一条未登记补提醒。
- 口服提醒按每条线的提醒时间生成，同一天同一时间合并。
- 免打扰时段内顺延；跨日顺延丢弃。
- 点击通知直达注射 / 口服登记。

**验收标准**

1. 注射提醒优先于口服提醒。
2. 已完成的计划不再提醒。
3. 停用线不再提醒。
4. Android 12+ 未授权精确闹钟时给出提示。
5. 引导期间点击通知，完成引导后补跳。
6. 通知失败不阻塞启动或数据写入。

### FR-08 部位轮换

**需求**

- 8 个皮下注射位点：腹部左上 / 右上 / 左下 / 右下、左 / 右大腿、左 / 右上臂。
- 推荐规则：排除最近 2 次、优先使用次数最少、优先不同侧、腹部优先。
- 首页和登记弹窗展示推荐位点；人体示意图可点选。

**验收标准**

1. 无历史时返回腹部左上。
2. 最近 2 次用过的位点不优先。
3. 同分时与最近一次不同侧。
4. 静脉输注不展示部位选择。

### FR-09 依从性与趋势

**需求**

- 注射线：按时 / 提前 / 延迟、平均偏差、漏打、未来计划、连续按时。
- 口服线：完成、漏服、完成率。
- 症状与注射时间线：竖线注射、圆点症状严重度。
- 所有统计标注「仅用于自我观察，不构成因果判断」。

**验收标准**

1. 偏差 = 实际 - 计划，保留 1 位小数。
2. 窗口内算按时；窗口外按早晚分类。
3. 逾期超过 7 天才计为漏用。
4. 口服完成率 = 完成 /（完成 + 漏用），保留 2 位小数。
5. 无数据时展示空状态。

### FR-10 疗效事件

**需求**

- 事件类型：疗效下降 / 失效 / 不耐受 / 抗药抗体 / 其他。
- 记录发生时间、备注，可同时停用用药线。
- 支持删除事件、恢复用药线。

**验收标准**

1. 发生时间不能晚于今天。
2. `dosesCount` 保存事件发生时的已完成次数快照。
3. 停用保留更早的停用时间。
4. 删除事件不会自动恢复用药线。

### FR-11 导入

**需求**

- 支持 `.xlsx` / `.xls` / `.json`，格式 v3，兼容 v1 / v2。
- 导入前预览数量。
- 药物按名称 / 通用名 / 商品名 / 目录名互认。
- 找不到用药线时自动新建。
- 重复记录跳过。

**验收标准**

1. 包含打卡记录时必须已有激活方案。
2. 每个数组最多 2000 条。
3. 时间必须能解析为本地时间；不存在的日期拒绝。
4. 同一份文件重复导入不会翻倍。
5. 症状新标签自动补进标签表。
6. 换机快照自动识别并走完整恢复。

### FR-12 导出

**需求**

- CSV：注射记录，UTF-8 BOM。
- Excel：注射 / 症状 / 药物 / 口服 / 用药线五张表。
- JSON：v3，可再导入。
- PDF：姓名、时间范围、注射记录、症状摘要、依从性统计。
- 换机快照：完整本地备份。
- 导出前提示健康信息风险。

**验收标准**

1. CSV / PDF 只包含注射记录（PDF 另有症状摘要）。
2. Excel 注射表包含状态列。
3. JSON 时间使用本地时间字符串。
4. PDF 时间范围支持 90 / 180 / 365 天。
5. 文件写入 cache 后通过系统分享。
6. 设备不支持分享时给出中文提示。

### FR-13 换机恢复

**需求**

- 旧手机导出 `bioclock-transfer` 快照。
- 新手机在引导页直接恢复。
- 恢复方案、用药线、阶段、口服计划、提醒、设置、标签、打卡、症状、疗效事件。

**验收标准**

1. 快照包含 `schemaVersion`，来自更新版本时拒绝导入。
2. 新设备无激活方案时按快照建方案。
3. 已有激活方案时只合并记录，不删除已有数据。
4. skipped / missed 打卡、原始计划时间、空部位保留。
5. 未被症状引用的标签也恢复。
6. 不继承 `app_lock`。

### FR-14 设置与基础管理

**需求**

- 药物管理：内置药只读名称 / 途径，可改默认剂量；自定义药可增删改；已被使用的药不能删除。
- 病种多选：只影响新建方案。
- 症状标签管理。
- 主题：跟随系统 / 浅色 / 深色。
- 免责声明与版本号。

**验收标准**

1. 内置药名称 / 通用名 / 商品名 / 途径不可修改。
2. 重名自定义药被拒绝。
3. 删除药物前检查是否被用药线引用。
4. 主题切换立即生效。
5. 免责声明可从设置打开。

### FR-15 隐私与安全

**需求**

- 数据仅本地 SQLite，无账号 / 网络 / 埋点。
- 应用锁：指纹 / 面容；后台超过 30 秒重新锁定。
- 清空数据：二次确认，删除业务数据，保留内置药并重新播种标签。

**验收标准**

1. 业务代码不发起网络请求（读取本地文件除外）。
2. 卸载即清除数据。
3. 应用锁开启前验证身份。
4. 清空数据后回到引导页。
5. 导出文件不写入仓库。

## 8. 非功能需求

### 8.1 数据与正确性

- 时间统一存 UTC 毫秒；导入 / 导出用本地时间字符串。
- 下次用药时间必须可重复推导，不能依赖缓存计划。
- 迁移只允许加列 / 加表；v5 重建是唯一历史例外。
- 清库逻辑必须保留内置药并重新播种症状标签。

### 8.2 性能与容量

- 单条线计划上限 100000，口服计划上限 20000，防止异常参数死循环。
- 单文件每个导入数组最多 2000 条。
- 通知单次最多 60 条。

### 8.3 可靠性

- 通知排程失败不回滚业务数据，必须提示用户。
- 导入主事务失败回滚；后置步骤失败会提示，但可能留下主数据。
- 应用锁验证失败不进入 App。

### 8.4 隐私与合规

- 不收集任何用户数据，不接第三方 SDK。
- 导出前提示包含健康信息。
- 症状 / 依从性 / 疗效内容保留自我观察声明。
- 不提供诊断、剂量调整或换药建议。

### 8.5 可用性与无障碍

- 可点击元素最小 44×44。
- 图标按钮有 `accessibilityLabel`，选中态使用 `accessibilityState`。
- 支持系统深浅色。
- 中文文案集中维护（当前仍有少量内联文案，属于技术债）。

### 8.6 平台

- Android 为主要目标平台。
- iOS 工程配置已就绪，但当前环境未做真机验证。
- Web 仅用于预览，`expo-sqlite` 能力受限。

## 9. 已知限制与本期不做

### 9.1 已知限制

1. 通知滚动预排 56 天，需要定期打开 App。
2. Android 12+ 精确闹钟权限影响准点。
3. 日历只展示注射计划。
4. CSV / PDF 注射表暂无状态列。
5. 稍后提醒分钟数只保存配置，未注册系统快捷操作。
6. 阶段级给药途径未建模（静脉诱导 + 皮下维持）。
7. 已有激活方案时换机只合并记录。
8. 首次引导只建一条用药线。
9. 免打扰跨日会丢弃该条提醒。
10. 应用锁是界面锁，不替代系统锁屏。

### 9.2 本期不做

- 账号、云同步、自动备份；
- 诊断、疗效判断、剂量 / 换药建议；
- 处方 OCR、药品条码识别；
- 社交、排行榜、提醒给家属；
- 口服小分子药物目录（可用自定义药物录入）；
- Web 完整支持。

## 10. 验收清单

- [ ] 首次引导能建立激活方案、用药线、提醒和设置。
- [ ] 登记注射后下次时间和通知同步更新。
- [ ] 口服完成 / 跳过、编辑、删除正常。
- [ ] 症状可记录严重度、疼痛、标签、体温和关联注射。
- [ ] 负荷 / 维持阶段按 doseNote 和 `repeatCount` 正确推进。
- [ ] 从下一针起调整间隔不影响历史。
- [ ] 停用 / 恢复用药线和治疗方案正常。
- [ ] 日历、趋势、依从性数据与打卡一致。
- [ ] 本地通知能按权限、免打扰和 56 天窗口排程。

## 11. 术语

| 术语 | 含义 |
| --- | --- |
| 治疗方案 | 一个可包含多条注射线 / 口服线的治疗组合 |
| 用药线 | 每种药一条，分为注射线和口服线 |
| 阶段 | 注射线的负荷 / 维持期，按顺序执行 |
| 主药 | 排程锚点跟随其实际注射时间的注射线 |
| 同步线 | 跟随主药针日注射的用药线 |
| 锚点 | 实际时间锚 / 计划时间锚 |
| 窗口 | 计划日前后允许的偏差天数 |
| 打卡 | 一次注射或口服记录，状态为 done / skipped / missed |
| 疗效事件 | 用户主动登记的疗效下降 / 失效 / 不耐受等事实 |
| 换机快照 | `bioclock-transfer` 格式的完整本地备份 |
